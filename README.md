# 归墟 · guixu

> *where all context returns* — 万水所归,而不盈。

归墟出自《列子·汤问》:东海之外的无底之谷,天下之水与天汉之流尽往其中,**注之不满,取之不竭**。

这个项目把它当作一个隐喻:**AI 协作过程里产生的一切原始上下文,都往这里归。** 不压缩、不丢弃、不过早结构化。

---

## 这是什么

一套**给 AI 协作过程做"原始事件留存"的最小方法**(method),不是一个框架,不是一个 schema。

主流做法是让 AI 完成任务、然后把经验压成 memory / skill / summary。归墟反过来:

> **结果只是上下文坍缩后的一个采样。真正有价值的是过程本身——prompt 怎么演化、为什么换方案、踩了什么坑、reasoning 的 trajectory。**

所以归墟存的是**完整原始过程**,把"提炼"留到读取时按需做,而不是写入时一次性压死。

## 唯一不变的根(the only invariant)

> **append-only · 原始 · 带时间戳 · 永不删除 · 永不就地压缩。**

这一条永不改。其余全是形态——要不要 graph、怎么索引、怎么检索、怎么切"事件"——随用随长,错了就换。

为什么偏偏是这条:append-only 的原始记录是**唯一不锁死未来的形态**。任何 schema 三个月后都可能后悔,而原始记录永远可以被未来的任意结构重新加工。premature structure 的危险本质是不可逆;原始记录是那个唯一可逆的选择。

## 两层结构

| 层 | 角色 | 特性 |
|---|---|---|
| **冷层 `raw/`** | 原始事件全量,按 session(一次坐下来干活)丢 | 完整、不可变、从不整段加载 |
| **热层 `index/`** | 事后涌现的提炼物:summary、关键词、指向 raw 的指针 | 有损、可重建、被加载进 context |

关键认知:**热层不是对价值的有损压缩,是指向无损仓库的门牌号。** 它丢的不是价值,是定位成本。你怕丢的"为什么",一字不少地留在冷层原文里。

"事件"(一次比赛 / 一个卡你三小时的 bug)是热层对冷层的**视图**,不是存储实体。同一批 raw 可以被多种颗粒度同时切,互不冲突——所以**颗粒度这种事永远不用提前决定**,它是读取时的事。

## 别人怎么用

```bash
git clone https://github.com/tljcpa/guixu
cd guixu
# 把一次 AI 协作过程原样丢进去(你自己的 raw/ 是 gitignore 的,不会污染本仓库)
cat 你的对话记录.txt | ./tools/add 某任务
```

你的真实事件只存在你本地,永不进 git。这个公开仓库只承载**方法、约定和工具**。

## 一条纪律(写给作者自己,也送给用的人)

归墟是真实工作的**排泄物**,不是宿主。
不要给它排独立工期。它只该在你做真实项目时被动长大。
任何一天若"在建设归墟"而没在做真实活——它就退化成了逃避。停手,去干活。
