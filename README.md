# 归墟 · guixu

> *where all context returns. keep the process, not the result.*
> 万水所归,而不盈。

> **guixu** — an append-only cold store for the *complete* raw context of AI-assisted work.
> Not memory, not summaries. The bet: the model is the runtime and raw context is the program —
> so ship the whole program, uncompressed, and let runtime intelligence reuse it.
> A summary throws away the one thing that mattered: the process.

---

我不信任 summary。

我不信任 memory、不信任 skill、不信任一切把经验"提炼"成几行要点的东西。
因为提炼的那一刻,你就已经替未来决定了"什么重要"——而你大概率决定错了。
那些当时看着像杂质的东西,往往才是日后真正有用的东西。

**结果只是上下文坍缩后的一个采样。**

真正发生过的是整个过程:prompt 怎么一版版变,方案为什么推倒重来,在哪一步卡了三个小时,绕了什么远路,最后为什么是这样而不是那样。这些,没有任何 summary 留得住。

所以归墟只做一件事:**把过程整个留下来,原封不动,永不压缩。**

## 唯一的规矩

不是框架,不是 schema,不是又一个 memory 系统。是一种近乎固执的留存方式,只有一条:

> **append-only · 原始 · 带时间戳 · 永不删除 · 永不就地压缩。**

这条永不改。其余全是形态——要不要检索、要不要图、怎么切"事件"——用到了再长,错了就换。

为什么偏偏是这条:任何结构三个月后都可能让你后悔,只有原始记录不会——它随时能被未来的任意结构重新加工。过早结构化的危险,本质是不可逆。**原始,是唯一可逆的选择。**

## 赌注

> 模型是 runtime。原始上下文是程序。
> 你要做的不是压缩程序、给它写注释,而是把整个程序原封不动地发运过去,让 runtime 自己跑。

我不需要懂它怎么用这些上下文。我只需要把上下文完整地交给它。剩下的,模型比我会。

## 一件真发生过的事

有一次,我把一个 session 的完整对话——整段,没删任何东西——原样喂给另一个全新的 session。
一件原本花了将近两天的活,它四个小时做完了。

我不知道它具体学到了什么,也不知道它怎么学的。端到端的黑盒。
我只确定一件事:我没给它任何提炼、任何要点、任何"经验总结"。我只给了完整的过程。

我没法向你证明这 4 小时全是"经验迁移"的功劳——也许那次任务本就简单些,也许是我自己变熟了。所以我不下结论。
我只把这件事摆在这,连同那份完整记录(脱敏后)。**你自己看。**

这正是归墟的态度:给你原文,不给你结论。

## 两层

- **冷层 `raw/`**:原始事件全量。按一次"坐下来干活"丢进去。完整、不可变、从不整段加载。
- **热层 `index/`**:事后才长出来的门牌号——指向某段 raw 的指针、一句话摘要。它不是对价值的压缩,是定位原文的地址。可以有损,可以推倒重建,因为真东西一字不少地躺在冷层。

"事件"(一次比赛、一个卡了三小时的 bug)是热层对冷层的一个**视图**,不是存储实体。同一批原始记录可以被多种颗粒度同时切。所以"多大算一个事件"这种问题永远不用提前回答——那是读取时的事。

## 它会撞墙,我知道

把整段对话喂进去,在"一个老师教一个学生"时成立。喂第二个老师,上下文窗口就爆了。
所以归墟将来唯一真正的难题,是"该把哪一段倒进去"——一个图书管理员。

但我现在不建它。等我真有了第十个、第二十个值得复用的事件、手动找不动了,那天再建。
在那之前提前建任何东西,都是另一种形式的逃避。

## 别人怎么用

闭环就三个动词:**存 → 洗 → 用**。

```bash
git clone https://github.com/tljcpa/guixu && cd guixu

# 存:把一次完整的 AI 协作过程原样丢进 raw/(按 session,零判断)
cat 你的完整对话记录.jsonl | ./tools/add 某任务

# 洗:给外部模型读之前,确定性预洗掉已知形状的活密钥(生成副本,不动原件)
./tools/defang raw/<事件目录>/transcript.jsonl raw/<事件目录>/transcript.defanged.jsonl

# 用:核心动词。拿这段过去的经验,起一个新会话去干新任务
./tools/use raw/<事件目录> "你的新任务" --run
```

`use` 是关键:它把"过去的完整过程 + 新任务"拼成一份上下文,喂给模型——让它继承你上次的决策、弯路和坑,而不是从零开始。这就是把"经验复用"那个手动动作自动化。

你的事件只存在你本地,**永不进 git**——这个仓库只承载方法、约定和工具。拿去,做你自己的归墟。

## 它现在能做什么 / 还不能做什么

- **能**:存完整过程、拆已知密钥、把一个过去事件整段喂给新任务(n=1 的经验迁移,已跑通)。
- **还不能**:当你有几十个事件时,自动**选**该喂哪一段——现在是手动指定。整段喂会撞上下文窗口的墙,所以"选哪段"(图书管理员)是下一个真问题。等手动找不动了再建,不提前造。
- **永远不做**:替模型做智能。归墟只负责把原始过程完整地交到模型面前,剩下的是模型的事。

## 一条纪律

归墟是真实工作的**排泄物**,不是宿主。
不要给它排工期。它只该在你做真正的活时,被动地长大。
哪一天你"在建设归墟"而没在干真正的活——它就成了逃避。停手,去干活。
